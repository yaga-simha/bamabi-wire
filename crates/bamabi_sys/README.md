# `bamabi_sys`

Strictly `#![no_std]`, **zero-dependency** C-ABI `0.3.0` (`0x0003_0000`) wire contract for `bamabi` (Layer 0 in [`bamabi-wire`](../../README.md)).

## Overview

This crate defines every cross-boundary type, descriptor, VTable header, error code, slot offset, and trait shared by the Bevy host, procedural macros, Rust guest SDK, `bevy_bql` compilers, and non-Rust guests via the [`include/bamabi.h`](../../include/bamabi.h) header generated by [`bamabi_sdk_gen`](../bamabi_sdk_gen):

- **Wire Primitives & Handles:** `FfiResult` (`18` codes including `CYCLE_DETECTED = 16`), `FfiBool`, `FfiOption<T>`, `StrView`, `FfiSlice<T>`, `FfiEntity`, `FfiChildOf`, `FfiDisabled` (`BAM_DISABLED_NAME`), `FfiAssetHandle`, `FfiAssetLoadState`, `BamComponent`, `BamSystem`, `BamSystemSet`, `BamSymbol`, `ComponentUuid` (keyed `const` SipHash-2-4-128 via `ComponentUuid::from_parts`), `ScheduleId`, `AccessMode`, `BamEventKind`, `BamChangeTicks`, `BamColumnInfo`, and `BAM_LOG_*` levels.
- **Extensible Descriptors & `offsets`:** `BamManifest`, all 68 live slots of `BamHostApi` (`552` B on 64-bit / `280` B on 32-bit, frozen `MIN_V0_2_SIZE` and `MIN_V0_3_SIZE`), `bamabi_sys::offsets` (`<FIELD>`, `OFF64_*`, `OFF32_*`, `SLOT_COUNT = 68`, `SIZE_64 = 552`, `SIZE_32 = 280`), `BamSystemDesc`, `BamQueryDesc`, `BamTermDesc`, `ComponentDesc` (including `schema_fingerprint`, `BamFieldDesc`, `BamFieldKind`, and `BamRequiredComponent`), `BamObserverDesc`, `BamTriggerDesc`, `BamRelationDesc`, `BamLayoutInfo`, `BamRowMigrateFn`, `BamScheduleSetDesc`, `VTableHeader`, and `ExtensibleStruct` prefix reading.
- **POD & Component Traits:** `ModComponent`, `RawInsertable`, and `AbiPod` (implemented strictly for fixed-width, bit-valid, zero-drop C-compatible types without implicit padding).

`bamabi_sys` has zero external dependencies (not even `alloc` or `std`) so host, proc-macro, SDK-generator, compiler, and guest crates share one identical binary contract without pulling in Bevy internals.

## Setup & Usage

Requires Rust edition `2024` (crate MSRV `1.87`; workspace `1.95`). Add `bamabi_sys` as a `#![no_std]`-compatible dependency:

```toml
[dependencies]
bamabi_sys = { git = "https://github.com/yaga-simha/bamabi-wire.git", branch = "main" }
```

To verify 32-bit and Wasm wire layouts locally, install the cross-targets:

```bash
rustup target add i686-unknown-linux-gnu wasm32-unknown-unknown
```

## Build & Lint

```bash
cargo check -p bamabi_sys
cargo check -p bamabi_sys --target i686-unknown-linux-gnu
cargo check -p bamabi_sys --target wasm32-unknown-unknown
cargo fmt -p bamabi_sys -- --check
cargo clippy -p bamabi_sys --all-targets --all-features -- -D warnings
RUSTDOCFLAGS="-D warnings" cargo doc -p bamabi_sys --no-deps --all-features
```

## Benchmarks & Performance

`bamabi_sys` is a Layer 0 wire-contract crate with **no Criterion benchmarks**; end-to-end runtime ECS and hot-reload benchmarks live in the Layer 4 **`bamabi-showcase`** repository (`docs/BENCHMARKS.md`). Within `bamabi_sys`, all layout invariants execute at compile time (`const` assertions), runtime lookups rely on pre-resolved `u32` handles and `offsets` constants with zero heap allocation, and `proptest_wire` case counts can be scaled with `PROPTEST_CASES=N` (capped at `4` cases under `cfg(miri)`).
